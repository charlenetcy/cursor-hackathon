# 🎨 Prompt & Style Service

The **Prompt & Style Service** is a production-ready REST API that handles AI-powered prompt parsing and real-time asset generation for the Multiplayer Parkour World game. This service provides normalized style tags, palettes, and dynamically generated skybox URLs that are consumed by the game server and clients.

## 🚀 Features

- **AI Prompt Parsing**: Converts natural language prompts into structured JSON using **Groq AI**
- **Real-time Asset Generation**: Generates skybox images dynamically using **Fal.ai**
- **Cloud Storage**: Automatically uploads and caches assets in **Supabase Storage**
- **Type Safety**: Fully typed TypeScript implementation with strict contract enforcement
- **Production Ready**: Complete integration with Groq, Fal.ai, and Supabase
- **Smart Caching**: In-memory cache for parsed prompts and asset reuse

## 📦 Tech Stack

- **Framework**: Express.js
- **Language**: TypeScript
- **AI Services**: 
  - Groq AI (LLM for structured JSON parsing)
  - Fal.ai (Image generation)
  - Supabase Storage (Asset hosting)
- **Testing**: Jest + Supertest
- **Security**: Helmet, CORS
- **Logging**: Morgan

## 🛠️ Installation & Setup

### 1. Install Dependencies

```bash
cd services/prompt
npm install
```

### 2. Configure Environment Variables

Create a `.env` file with your API keys:

```bash
# Groq AI - Get from https://console.groq.com/keys
GROQ_API_KEY=your_groq_api_key_here

# Fal.ai - Get from https://fal.ai/dashboard/keys
FAL_KEY=your_fal_api_key_here

# Supabase - Get from your project settings
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_ANON_KEY=your_supabase_anon_key_here
SUPABASE_BUCKET=game-assets
```

📖 See [ENV_SETUP.md](./ENV_SETUP.md) for detailed setup instructions.

### 3. Create Supabase Storage Bucket

1. Go to your Supabase project dashboard
2. Navigate to **Storage** → Create bucket: `game-assets`
3. Make it **public** for URL access

### 4. Start the Service

```bash
# Development mode (with hot reload)
npm run dev

# Build for production
npm run build

# Run production server
npm start

# Run tests
npm test

# Run tests in watch mode
npm run test:watch
```

## 📡 API Endpoints

### Health Check
```
GET /health
```
Returns service status, cache size, and integration configuration.

### Parse Prompt (Groq AI)
```
POST /prompt/parse
Content-Type: application/json

{
  "text": "Japanese temple at sunset"
}
```

**Response (201 Created):**
```json
{
  "promptId": "phash_a1b2c3d4",
  "palette": ["#d32f2f", "#ffd700", "#1a1a1a"],
  "motifs": ["pagoda", "lanterns", "torii"],
  "mechanics": [],
  "difficulty": 3
}
```

💡 **Note:** Palette and motifs are AI-generated by Groq based on the prompt text.

### Get Style by PromptId (Fal.ai + Supabase)
```
GET /style/byPromptId/:id
```

**Response (200 OK):**
```json
{
  "promptId": "phash_a1b2c3d4",
  "palette": ["#d32f2f", "#ffd700", "#1a1a1a"],
  "skyboxUrl": "https://xxxxx.supabase.co/storage/v1/object/public/game-assets/skyboxes/phash_a1b2c3d4.jpg",
  "textureIds": ["tx_phash_a1b2c3d4_001"],
  "motifIds": ["pagoda", "lanterns", "torii"],
  "version": "v1"
}
```

⏱️ **Note:** First call may take 20-40 seconds for asset generation. Subsequent calls use cached assets.

📖 See [API_DOCUMENTATION.md](./API_DOCUMENTATION.md) for complete API reference.

## 🔒 API Contracts

All API endpoints strictly enforce the shared JSON contracts defined in `Team_Split_and_Contracts.md`:

- **API Version**: All responses include `"version": "v1"`
- **Frozen Interfaces**: No breaking changes to field names or types
- **Backward Compatible**: New fields added as optional only

This service is consumed by:

- **Game Server** (Developer A): Fetches styles via `GET /style/byPromptId/:id`
- **Client** (Developer B): Uses CDN URLs from style responses

All integration is via the shared JSON contracts, allowing fully independent development.
